# Архитектура проекта

Данный файл содержит подробный разбор архитектуры веб-приложения. Проект организован по принципу монорепозитория, объединяющего бэкенд на **Django (Python)**, фронтенд на **Vite (JavaScript)**, контейнеризацию через **Docker** и автоматический деплой (CI/CD) с помощью **GitHub Actions**. Структура и конфигурация контейнеризации приложения может быть создана для двух режимов: **локальной разработки** и **продакшн-деплоя**. Конфигурация проекта задается через переопределения compose-файлов (базовый `docker-compose.yml` расширяется с помощью `.dev.yml` или `.prod.yml`).

## 2. Схема для локальной разработки (Development)

В режиме разработки упор сделан на динамическое обновление кода (Hot Reload) как на фронтенде, так и на бэкенде.

### Графическая схема (Dev)
```text
 [ Браузер разработчика ]
           │
           ├──────────────────────────────┐ (запросы /api/*)
           ▼                              ▼
    ┌──────────────────┐          ┌──────────────────┐
    │ Frontend (Vite)  │          │ Backend (Django) │ (python manage.py runserver)
    │  Порт: 5173      │          │  Порт: 8000      │
    └──────────────────┘          └────────┬─────────┘
                                           │
                                           ▼
                                  ┌──────────────────┐
                                  │    PostgreSQL    │
                                  │  Порт: 5432      │
                                  └──────────────────┘
```

* **Frontend:** Запускается через `Dockerfile.dev`. Код монтируется через `volumes` прямо из папки `./frontend_project`. Добавлены интерактивный режим (`stdin_open`, `tty`) для корректной работы Node.js / Vite.
* **Backend:** Запускается в режиме `runserver` на порту `8000`. Папка `./backend_project` смонтирована как volume для авто-перезапуска при изменении `.py` файлов.
* **База данных:** Доступна на стандартном порту `5432` снаружи для удобства отладки.

## 3. Схема для деплоя (Production: Gunicorn с 3 воркерами)

В продакшн-окружении бэкенд закрывается от прямого доступа извне, а контейнер `frontend` (со встроенным Nginx) берет на себя роль Reverse Proxy, отдавая статику/медиа и проксируя запросы к API.

### Графическая схема (Prod)
```text
                     [ Внешний клиент / Браузер ]
                                  │
                                  ▼ (Порт 80)
                        ┌───────────────────┐
                        │ Frontend (Nginx)  │
                        └─────────┬─────────┘
                                  │
         ┌────────────────────────┼────────────────────────┐
         │ (Если статика React)   │ (Если статика/медиа)   │ (Если /api/* или /admin/*)
         ▼                        ▼                        ▼
┌───────────────────┐    ┌───────────────────┐    ┌─────────────────────────────────┐
│ Собранный React   │    │  backend_static/  │    │      Балансировщик Gunicorn     │
│ (внутри образа)   │    │  backend_media/   │    │     (Внутренний порт 8000)      │
└───────────────────┘    └───────────────────┘    └────────────────┬────────────────┘
                                                           │
                                   ┌───────────────────────┼───────────────────────┐
                                   │ (Распределяет запрос) │                       │
                                   ▼                       ▼                       ▼
                        ┌────────────────────┐  ┌────────────────────┐  ┌────────────────────┐
                        │      Воркер 1      │  │      Воркер 2      │  │      Воркер 3      │
                        │ (Процесс Django 1) │  │ (Процесс Django 2) │  │ (Процесс Django 3) │
                        └──────────┬─────────┘  └──────────┬─────────┘  └──────────┬─────────┘
                                   │                       │                       │
                                   └───────────────────────┼───────────────────────┘
                                                           │ (Запросы к БД)
                                                           ▼
                                                ┌────────────────────┐
                                                │     PostgreSQL     │
                                                │ (Порт скрыт извне) │
                                                └────────────────────┘
```

* **Frontend (Reverse Proxy):** Слушает внешний порт `80`. Образ собирается через `Dockerfile.prod`. К нему подключены именованные тома `django_static` и `django_media`. Он раздает статические файлы напрямую, а динамические запросы проксирует на `backend:8000`.
* **Backend:** Внешние порты отключены (`ports: []`). Запросы принимает только из внутренней сети Docker. Запускается через **Gunicorn с 3 воркерами** под управлением `core.wsgi:application`. Генерирует статику и медиа в общие тома.
* **База данных:** Настройки считываются из общего файла конфигурации `.env`.
